# Добавление UI-теста

1. Новый класс в `src/test/java/qa/aifirst/`, наследуйся от `TestBase` —
   там общая настройка Selenide и Allure, не дублируй её в тесте.
2. Пиши в Selenide-стиле: `open(URL)`, `$`, `shouldHave` — без
   явных вызовов WebDriver и ручных ожиданий. URL страницы на
   GitHub Pages смотри в `LoginTest`.
3. Один тест = один сценарий: не объединяй разные сценарии
   в один метод.
4. `@DisplayName` на русском — имя теста читается как требование.
5. Эталонный пример — `LoginTest.java`; локаторы, креды и тексты
   формы смотри в `index.html`, не выдумывай.
6. Тексты ошибок и локаторы бери из `index.html` дословно. Ошибку
   проверяй так: `shouldHave(exactText("..."), cssClass("error"))`;
   для «вход не выполнен» добавь `shouldNotHave(cssClass("success"))`.
   Эталон негативных сценариев — `LoginNegativeTest.java`.
7. Одинаковый сценарий с разными данными — `@ParameterizedTest` +
   `@CsvSource` (пустая строка — `''`); разные ожидаемые сообщения —
   отдельные тесты.
8. Перед коммитом прогони `./gradlew test` — всё должно быть зелёным.
   Тесты открывают версию с GitHub Pages: новое поведение продукта
   красное, пока правки не в `main` (ADR-0006). На Windows, если
   падают сравнения русского текста, нужна UTF-8 (`JAVA_TOOL_OPTIONS=
   -Dfile.encoding=UTF-8`) и пересборка тестов.
